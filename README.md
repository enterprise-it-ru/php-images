# php-images

Универсальные образы PHP-FPM с набором часто используемых расширений. Образы собираются в GitHub Actions и публикуются в публичный реестр `ghcr.io/enterprise-it-ru/php`.

Зачем это нужно. Чтобы поставить расширение, `install-php-extensions` скачивает его исходники с PECL и GitHub. С наших серверов эти ресурсы доступны не всегда, и сборка образа проекта на сервере падает. Здесь расширения собираются заранее в GitHub Actions. Проект берёт готовый образ, и на сервере за расширениями ходить не нужно.

## Версии и теги

| PHP | Debian   | Плавающий тег | Еженедельная пересборка |
|-----|----------|---------------|-------------------------|
| 7.4 | bullseye | `7.4-fpm`     | нет                     |
| 8.1 | trixie   | `8.1-fpm`     | нет                     |
| 8.2 | trixie   | `8.2-fpm`     | да                      |
| 8.3 | trixie   | `8.3-fpm`     | да                      |
| 8.4 | trixie   | `8.4-fpm`     | да                      |
| 8.5 | trixie   | `8.5-fpm`     | да                      |

Каждая сборка публикует два тега:

- `8.3-fpm` — плавающий, всегда указывает на последнюю сборку;
- `8.3-fpm-20261019-15` — снимок: дата сборки и номер запуска workflow. Снимки никогда не перезаписываются.

**В проектах указывайте снимок.** Тогда образ меняется только после явного обновления тега, а не при очередной пересборке. Список тегов есть на [странице пакета](https://github.com/orgs/enterprise-it-ru/packages/container/package/php) и в сводке каждого запуска workflow.

Образы собираются для `linux/amd64` и `linux/arm64`. Реестр публичный, поэтому `docker login` для скачивания не нужен.

PHP 7.4 и 8.1 больше не поддерживаются, официальные образы для них не обновляются. Поэтому их образы пересобираются только после изменений в этом репозитории. Для 7.4 пакеты Debian берутся с `archive.debian.org`, потому что релиз bullseye тоже снят с поддержки.

## Состав образа

**Включены по умолчанию:** apcu, bcmath, bz2, calendar, exif, gd (с FreeType, JPEG, PNG, WebP), gmp, igbinary, imagick, intl, mysqli, opcache, pcntl, pdo_mysql, pdo_pgsql, pgsql, redis, soap, sockets, xsl, zip.

**Установлены, но выключены:** xdebug, pcov, mongodb, amqp, memcached. Как их включить, описано [ниже](#включить-дополнительное-расширение).

Кроме расширений, в официальном образе PHP есть ctype, curl, dom, fileinfo, mbstring, openssl, pdo_sqlite, sodium, tokenizer, xml и другие стандартные модули. Сверху в образ добавлены:

- `composer` — последняя версия на момент сборки;
- `git` и `unzip` — нужны composer;
- `install-php-extensions` — пригодится там, где есть доступ в сеть.

Посмотреть состав конкретного образа:

```shell
docker run --rm ghcr.io/enterprise-it-ru/php:8.3-fpm php -m
docker run --rm ghcr.io/enterprise-it-ru/php:8.3-fpm cat /usr/local/share/php-extensions/optional
```

В PHP 8.5 opcache встроен в ядро и всегда загружен, его настраивают только через ini.

## Использование в проекте

### Dockerfile

В базовом образе не выбран `php.ini`, не задан пользователь и нет настроек проекта: всё это определяет проект. Пример с отдельными стадиями для разработки и продакшена:

```dockerfile
FROM ghcr.io/enterprise-it-ru/php:8.3-fpm-20261019-15 AS php_base

COPY --link app.ini $PHP_INI_DIR/conf.d/

FROM php_base AS php_dev

RUN mv "$PHP_INI_DIR/php.ini-development" "$PHP_INI_DIR/php.ini" \
    && docker-php-ext-enable xdebug
COPY --link app.dev.ini $PHP_INI_DIR/conf.d/

RUN usermod -u 1000 www-data

USER www-data
WORKDIR /app

FROM php_base AS php_prod

RUN mv "$PHP_INI_DIR/php.ini-production" "$PHP_INI_DIR/php.ini"
COPY --link app.prod.ini $PHP_INI_DIR/conf.d/

USER www-data
WORKDIR /app
```

Как и официальный образ PHP, базовый образ запускается от `root`. Пользователя задаёт проект, как в примере выше.

### Включить дополнительное расширение

Выключенные расширения уже скомпилированы и лежат в образе. `docker-php-ext-enable` только создаёт для них ini-файл, доступ в сеть не нужен:

```dockerfile
RUN docker-php-ext-enable mongodb amqp
```

Пример настройки xdebug для разработки в `app.dev.ini`:

```ini
xdebug.mode = debug
xdebug.start_with_request = trigger
xdebug.client_host = host.docker.internal
```

### Выключить ненужное расширение

Включённое расширение выключается удалением его ini-файла:

```dockerfile
RUN rm "$PHP_INI_DIR/conf.d/docker-php-ext-imagick.ini"
```

### Очереди, cron и консольные команды

В FPM-образе есть и `php` CLI, отдельный CLI-образ не нужен. Воркеры запускаются из того же образа:

```yaml
services:
  queue:
    build:
      context: .docker/php-fpm
      target: php_prod
    command: php artisan queue:work
```

### Обновление образа

1. Возьмите свежий снимок нужной версии на [странице пакета](https://github.com/orgs/enterprise-it-ru/packages/container/package/php).
2. Замените тег в `FROM` и пересоберите образ проекта.

Если проекту нужен не снимок, а плавающий тег (`8.3-fpm`), собирайте образ с `--pull`, например `docker compose build --pull`. Иначе Docker продолжит использовать скачанную раньше версию.

### Нужного расширения нет в образе

- Если расширение пригодится и другим проектам, добавьте его в этот репозиторий (см. [ниже](#добавить-или-убрать-расширение)).
- Если оно нужно только одному проекту, ставьте его через `install-php-extensions` там, где есть доступ в сеть: в CI проекта или локально. Не ставьте его при сборке на сервере.

## Разработка

### Структура репозитория

| Файл                          | Назначение                                                                |
|-------------------------------|---------------------------------------------------------------------------|
| `Dockerfile`                  | Один на все версии: списки расширений, версия установщика, пакеты apt     |
| `versions.json`               | Версии PHP, релиз и зеркало Debian, признак еженедельной пересборки       |
| `tests/smoke.sh`              | Проверка собранного образа                                                |
| `.github/workflows/build.yml` | Сборка, проверка и публикация                                             |

### Добавить или убрать расширение

1. Измените `EXTENSIONS` (включены по умолчанию) или `OPTIONAL_EXTENSIONS` (установлены, но выключены) в `Dockerfile`. Названия расширений и поддерживаемые версии PHP есть в [списке установщика](https://github.com/mlocati/docker-php-extension-installer#supported-php-extensions).
2. Проверьте сборку локально хотя бы на крайних версиях: `make test PHP=7.4` и `make test PHP=8.5`.
3. Откройте pull request. CI соберёт и проверит все версии, но ничего не опубликует.
4. После мержа в `main` образы всех версий пересоберутся и опубликуются с новыми снимками.

Тяжёлые и редко нужные расширения (grpc, swoole, protobuf) в образ намеренно не входят: каждое компилируется больше 20 минут.

### Добавить версию PHP

Добавьте запись в `versions.json`:

```json
{ "php": "8.6", "debian": "trixie" }
```

Дополнительные поля:

- `"scheduled": false` — для версий, у которых больше не выходит обновлений: их не будут пересобирать по расписанию;
- `"debian_mirror": "http://archive.debian.org"` — для снятых с поддержки релизов Debian. С обычных зеркал их пакеты удаляют, и без этого поля `apt-get` падает с ошибкой 404.

### Обновить установщик расширений

Поменяйте `IPE_VERSION` в `Dockerfile` на нужный [релиз](https://github.com/mlocati/docker-php-extension-installer/releases).

### Локальная сборка

Нужны Docker и `jq`:

```shell
make test PHP=8.4   # собрать php-images:8.4-fpm и прогнать smoke-тест
make build PHP=8.4  # только собрать
```

Smoke-тест проверяет:

- включённые расширения загружены;
- дополнительные выключены и включаются через `docker-php-ext-enable`;
- PHP запускается без предупреждений;
- gd собран с нужными форматами;
- конфигурация php-fpm валидна;
- composer и git работают.

### CI

| Событие                                     | Что происходит                                                                  |
|---------------------------------------------|---------------------------------------------------------------------------------|
| Pull request                                | Сборка и проверка всех версий без публикации                                    |
| Push в `main` с изменениями образа или CI   | Сборка, проверка и публикация всех версий                                       |
| По расписанию (понедельник, 03:00 UTC)      | Пересборка версий без `"scheduled": false`: подтягиваются патчи PHP и Debian    |
| Ручной запуск (Run workflow)                | Сборка выбранных версий (поле `php`, например `8.3 8.4`) или всех, если пусто   |

Каждая пара «версия + архитектура» собирается на своём нативном раннере (`ubuntu-24.04` и `ubuntu-24.04-arm`). Smoke-тест идёт до публикации. Затем задача `merge` объединяет обе архитектуры в один тег. Если сборка одной версии упала, остальные всё равно публикуются.

### Первоначальная настройка

1. В настройках организации разрешите публичные пакеты: Settings → Packages → Package creation → Public.
2. После первой публикации откройте пакет `php` → Package settings → Change visibility → Public.

Доступ к пакету на запись репозиторий получает автоматически: пакет создаётся его же workflow. Связь пакета с репозиторием задаёт аннотация `org.opencontainers.image.source`.
